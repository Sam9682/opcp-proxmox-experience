Core Concepts

Difficulty: Beginner · Estimated time: 15 min

Before diving into the hands-on labs, let's understand the key technologies that make GPU passthrough on Proxmox possible.

Proxmox VE

Proxmox Virtual Environment is an open-source server virtualization platform based on Debian. It integrates KVM hypervisor and LXC containers with a powerful web UI, making it ideal for running GPU workloads in VMs.

  • KVM — Kernel-based Virtual Machine, provides hardware-level virtualization
  • QEMU — Machine emulator, handles VM device emulation
  • Q35 — Modern machine type that supports PCIe passthrough
  • OVMF — UEFI firmware for VMs (required for GPU passthrough)

PCI Passthrough

PCI passthrough allows a physical PCI device (like a GPU) to be directly assigned to a virtual machine, bypassing the hypervisor. The VM gets near-native performance from the device.

IOMMU (Input-Output Memory Management Unit)

IOMMU provides memory isolation between devices and the host. It ensures that a passed-through device can only access the memory regions assigned to its VM.

  • Intel VT-d — Intel's IOMMU implementation (intel_iommu=on)
  • AMD-Vi — AMD's IOMMU implementation (amd_iommu=on)
  • IOMMU Groups — logical groupings of PCI devices that must be passed through together

VFIO (Virtual Function I/O)

VFIO is a Linux kernel framework that provides user-space drivers with direct device access. For GPU passthrough, we bind the GPU to the vfio-pci driver instead of the native GPU driver (e.g., nouveau or nvidia). 

# Check current driver binding
lspci -ks 41:00.0

# Expected after VFIO binding:
# Kernel driver in use: vfio-pci

Architecture Overview

The automation workflow follows these stages:

StageComponentDescription
1ProvisionerCreates a baremetal instance on OpenStack
2InstallerInstalls Proxmox VE packages on Debian
3IOMMU ConfigEnables IOMMU in GRUB and loads VFIO modules
4GPU DetectorDetects NVIDIA/AMD GPUs via lspci
5VFIO ManagerBinds GPUs to vfio-pci driver
6VM CreatorCreates a Q35/OVMF VM with hostpci device
7ValidatorVerifies GPU is visible inside the VM

Key Configuration File

The entire workflow is driven by a YAML configuration:

openstack:
  auth_url: "https://auth.cloud.ovh.net/v3"
  region: "GRA9"

instance:
  base_image_name: "Debian 12"
  flavor_name: "b3-8"

proxmox:
  version: "8.2"
  enterprise_repo: false
  network_bridge: "vmbr0"

gpu_passthrough:
  enabled: true
  iommu_type: "intel"
  blacklist_drivers:
    - nouveau
    - nvidia
    - nvidiafb
    - nvidia_drm

test_vm:
  enabled: true
  name: "gpu-test-vm"
  memory_mb: 8192
  cores: 4
  machine_type: "q35"
  bios: "ovmf"
