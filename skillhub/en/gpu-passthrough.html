GPU Passthrough (IOMMU & VFIO)

Difficulty: Advanced · Estimated time: 35 min

This is the core lesson of the training. You'll learn how IOMMU and VFIO work together to isolate GPU devices from the host and make them available for VM passthrough.

Step 1: GPU Detection

The automation detects NVIDIA and AMD GPUs using lspci: 

# Detect VGA/3D controllers
lspci -nn | grep -iE '(vga|3d|display)'

# Example output:
# 41:00.0 3D controller [0302]: NVIDIA Corporation Tesla T4 [10de:1eb8] (rev a1)

Key information extracted:

FieldExamplePurpose
PCI ID0000:41:00.0Unique device address
Vendor ID10deNVIDIA identifier
Device ID1eb8Tesla T4 identifier
IOMMU GroupvariesIsolation group

Step 2: IOMMU Configuration

IOMMU must be enabled in GRUB kernel parameters. The automation detects whether to use Intel VT-d or AMD-Vi based on your configuration: 

# For Intel CPUs:
# GRUB_CMDLINE_LINUX_DEFAULT="quiet intel_iommu=on iommu=pt"

# For AMD CPUs:
# GRUB_CMDLINE_LINUX_DEFAULT="quiet amd_iommu=on iommu=pt"

# The automation updates GRUB:
sed -i 's/GRUB_CMDLINE_LINUX_DEFAULT="\(.*\)"/GRUB_CMDLINE_LINUX_DEFAULT="\1 intel_iommu=on iommu=pt"/' /etc/default/grub
update-grub

Step 3: VFIO Kernel Modules

The VFIO framework requires several kernel modules to be loaded at boot: 

# Required modules (written to /etc/modules-load.d/vfio.conf):
vfio
vfio_iommu_type1
vfio_pci
vfio_virqfd

# Update initramfs to include VFIO modules early in boot
update-initramfs -u -k all

Step 4: Blacklist GPU Drivers

Native GPU drivers must be blacklisted to prevent them from claiming the device before VFIO can bind to it: 

# /etc/modprobe.d/blacklist-gpu.conf
blacklist nouveau
blacklist nvidia
blacklist nvidiafb
blacklist nvidia_drm

# Ensure VFIO loads before any GPU driver
softdep nouveau pre: vfio-pci
softdep nvidia pre: vfio-pci
softdep nvidiafb pre: vfio-pci
softdep nvidia_drm pre: vfio-pci

Step 5: VFIO-PCI Device Binding

Configure VFIO-PCI to claim specific GPU devices by vendor:device ID pairs: 

# /etc/modprobe.d/vfio.conf
options vfio-pci ids=10de:1eb8

# The IDs correspond to your GPU(s). Multiple GPUs:
# options vfio-pci ids=10de:1eb8,10de:10f0

Step 6: Udev Rules

Persistent udev rules ensure VFIO binding survives across reboots: 

# /etc/udev/rules.d/99-vfio.rules
ACTION=="add", ATTR{vendor}=="0x10de", ATTR{device}=="0x1eb8", DRIVER=="", ATTR{driver_override}="vfio-pci"

# Reload udev rules
udevadm control --reload-rules

Step 7: Verification (After Reboot)

After reboot, verify IOMMU is enabled and GPUs are bound to VFIO:

# Check IOMMU is enabled
dmesg | grep -i iommu | head -5
# Should show: DMAR: IOMMU enabled

# Count IOMMU groups
find /sys/kernel/iommu_groups/ -maxdepth 1 -mindepth 1 -type d | wc -l

# Verify GPU is bound to vfio-pci
lspci -ks 41:00.0
# Kernel driver in use: vfio-pci

Troubleshooting

  • IOMMU not enabled: Check BIOS/UEFI settings for VT-d or AMD-Vi
  • GPU still using nvidia driver: Verify blacklist is in initramfs (lsinitramfs)
  • IOMMU group too large: May need ACS override patch (not recommended for production)
  • Audio device in same group: Pass through both GPU and its audio controller
