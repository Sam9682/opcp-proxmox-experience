Provisionnement Baremetal

Difficulté : Intermédiaire · Temps estimé : 25 min

Dans cette leçon, vous apprendrez comment l'automatisation provisionne une instance baremetal GPU sur OVHcloud OpenStack. Le provisioner s'authentifie via des identifiants d'application, crée une instance avec le flavor spécifié et attend la connectivité SSH.

Authentification

L'outil utilise le SDK OpenStack avec des identifiants d'application. Cela évite de stocker un nom d'utilisateur/mot de passe et fournit un accès scopé. 

# config.yaml — section identifiants OpenStack
openstack:
  auth_url: "https://auth.cloud.ovh.net/v3"
  region: "GRA9"
  auth_type: "v3applicationcredential"
  application_credential_id: "${OS_APPLICATION_CREDENTIAL_ID}"
  application_credential_secret: "${OS_APPLICATION_CREDENTIAL_SECRET}"

Les variables d'environnement sont résolues au runtime. Exportez-les avant l'exécution :

# Définir vos identifiants
export OS_APPLICATION_CREDENTIAL_ID="votre-credential-id"
export OS_APPLICATION_CREDENTIAL_SECRET="votre-credential-secret"

Spécification de l'instance

ParamètreDéfautDescription
base_image_nameDebian 12Image OS de base
flavor_nameb3-8Flavor baremetal avec GPU
ssh_key_name—Nom de la clé SSH dans OpenStack
network_nameExt-NetRéseau à attacher
ssh_usernamedebianUtilisateur par défaut pour SSH

Workflow de provisionnement

  1. Authentification à l'API OpenStack
  2. Création d'un serveur avec l'image, le flavor et la clé spécifiés
  3. Attente du statut ACTIVE (timeout : 600s)
  4. Récupération de l'adresse IP
  5. Établissement de la connexion SSH (timeout : 300s)
# Équivalent en commandes manuelles :
openstack server create \
  --image "Debian 12" \
  --flavor "b3-8" \
  --key-name "my-key" \
  --network "Ext-Net" \
  --security-group "default" \
  proxmox-gpu-node

# Attendre qu'elle soit active
openstack server show proxmox-gpu-node -f value -c status

# Obtenir l'IP
openstack server show proxmox-gpu-node -f value -c addresses

Connexion SSH

# Équivalent manuel
ssh -i ~/.ssh/id_rsa debian@<instance-ip>

Timeouts

timeouts:
  instance_ready: 600    # Attente max pour instance ACTIVE
  ssh_connection: 300    # Attente max pour connectivité SSH
  proxmox_install: 1200  # Temps max pour installation Proxmox
  reboot_wait: 300       # Attente max après reboot
  gpu_setup: 600         # Temps max pour configuration GPU
  vm_creation: 300       # Temps max pour création VM
